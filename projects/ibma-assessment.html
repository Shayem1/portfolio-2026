IBMA Assessment

A grading web app running for an accredited Australian college — real users, real auth, real data boundary.

JWTsession auth for students + admins
20/40/40example task weighting (3-task unit)
app-onlyAzure AD credential, least privilege
1SharePoint folder holds all data

What it does

  • Multiple-choice quizzes (task 1) plus written tasks with long/short answers, editable tables and optional file uploads (tasks 2+).
  • Unit progress is a weighted blend across tasks (task 1 = 1/(2n−1), each later task = 2/(2n−1)).
  • Server-side grading and question shuffling (15-question subsets); saved-state and lock handling per attempt.

Architecture

Browser (React SPA)
   |  HTTPS  (Bearer JWT)
   v
Netlify Functions (Node)
   +-- login / admin-login   -> reads logins from SharePoint, returns JWT
   +-- get-questions         -> shuffled MCQ subset / written task (answers stripped)
   +-- submit                -> grades task 1, writes attempt-N.json, returns feedback
   v
Microsoft Graph (Azure AD app-only credential) -> SharePoint folder (all app data)

For an accredited RTO (National Provider 41025) this is also a data-protection exercise: app-only Graph access, answers never sent to the client for written tasks, and record handling governed by the same IDS/ethics framework published on Scanner-for-IBMA.
