Discord bot: an agent with layered memory

An always-on Discord presence driven only by locally served models, built around a persistent memory system that compresses when a channel goes quiet.

The entity loop

Batched turns queue everything

Every allowed non-bot message is appended to the channel's archive and queued. Chatter accumulates for 8 seconds, then one batch becomes one model turn presented as dated, author-prefixed lines. Directed messages (@name, replies) jump the queue; a message arriving mid-generation stays queued until the next turn.

The choice to speak

Every turn ends with either a reply or a stay_quiet(reason) tool call. Quiet turns send nothing, log their reason, and an empty final reply counts as quiet too.

Self-written state

Relationship notes per user and a growing interest catalogue are written only by the model through update_relationship / update_interests, then injected into every turn once non-empty. The interests store has hard caps (20 topics, 12 facets per topic, 2500 rendered chars) so self-curated memory cannot grow unbounded.

Memory pipeline: persistent by default, compressed when idle

Archive first: the truth layer never compresses

Every message and every reply is appended verbatim to a per-channel JSONL archive with a monotonic sequence number. Distillation never touches it; keyword search over the archive always returns exact, author-prefixed hits with dates.

Five distillation tiers

The undistilled tail folds into context up to a 64k-token seed region (96k headroom). When it overflows, the oldest stretch is distilled into tier D1 (40k budget, hour-stamped spans); each tier over budget distills its oldest entries one tier deeper: D2 20k, D3 10k, D4 5k, D5 50k terminal. Distilled entries keep actors, dates and what mattered, and an over-budget entry is truncated to fit its budget.

Forgetting follows written rules

Entries tagged casual die at D3; only important survives deeper. D5 overflow drops the oldest first and is never re-distilled. A distillation that returns nothing holds the tier in place and retries the next cycle with the tier intact.

Idle-only distillation, interrupt-safe

Compression runs 120 seconds after a channel goes quiet, in blocks of at most 50 messages / 1 hour. New activity hard-cancels a running cycle: the model request is aborted, nothing is written, the cursor does not move. Schedulers arm at login, so a restart with a backlog distills without needing a new message.

Recovery and backfill

At login, past Discord history merges into the archive chronologically with renumbered sequences and ID dedupe; after the first distill it only fills gaps newer than the latest distillation cursor, so distilled data is never re-fetched or duplicated. State files save via debounced atomic writes (temp file + rename), so a crash mid-save cannot corrupt the store. Deleting the data directory is the only full reset.

Recall is a tool call

memory_search runs keyword-AND queries with optional date ranges across all tiers plus the full archive. Tier hits arrive stamped ([D3 2026-01-01→2026-01-08 | important]); archive hits arrive verbatim. Result count and total characters are capped so recall cannot blow the context budget it protects.

Constraints the design had to solve

Byte-stable prompts for a cache-hungry local model

The prompt assembles in a fixed order (persona, D5→D1, acting brief, raw region, today clock, relationships, interests) with a pinned persona block of at least 2048 tokens, so the prefix is byte-identical across turns and the local serving stack's prompt cache reuses it; only the tail changes. Distillation calls run with checkpointing suppressed, so background compression never evicts the live turn's cache checkpoint.

Discord's 2000-character wall

A fence-aware chunker splits replies at paragraph, then line, then word boundaries, and oversized code fences are re-fenced per chunk so every Discord message renders its own valid code block. The chunker treats the 2000-character platform limit as a design input.

Media failures become annotations

A dead, timed-out or disabled media upstream arrives as a skipped: reason note and the chat turn still proceeds; timed-out upstreams are discarded and respawned on next use. Per-call timeouts are fixed in code (120–900 seconds by workload).

Lazy, local-only media toolbox

Image store, whisper, video and reverse-image search run as local Python MCP subprocesses spawned on first use and closed after 300 idle seconds: idle channels cost nothing, and no cloud AI service is ever contacted for understanding. The upstreams are the same MCP servers documented on the Strata stack page.

A URL trust model with one gate

A link allowlist plus Discord's CDN is always fetchable. A user-written external link gets one VirusTotal safety check (safe under 50% of engines flagging) and is then remembered as safe, skipping repeat checks. A model-invented link is restricted to the allowlist, remembered-safe links and public hosts. Private or internal hosts are never fetched, and redirects are re-checked hop by hop. Reverse-image lookups carry a daily budget (25) with per-URL caching.

Two brain profiles

Primary: the local Strata server's model via its OpenAI-compatible API (vision included). Fallback profile: a bundled llama.cpp CPU model launched by its own scripts, text-only by configuration cap, so the bot still runs when the GPU server is down or occupied.

Evidence

  • Unit suite runs without Discord and without network: 741 assertions passing, 0 failures on this machine
  • Offline smoke test checks the wiring plus serving-stack reachability before any login
  • Persona and behavior live in plain-text files the operator edits (identity, voice, boundaries); the architecture is described in the repo's own agent-facing documentation
  • Media understanding reuses the PF2 MCP servers (image store, whisper + diarization, video grounding, reverse search); the fallback brain is a vendored llama.cpp runtime profile
  • Repository and chat archive stay private: this page documents behavior and constraints, and the Discord messages stay in the private repo
