The problem, in its time

In October 2025, no mainstream model pipeline could produce a presentable document. In my judgement at the time, frontier cloud models barely formatted a table or chose a font: their "documents" were notepad output with slightly cleaner spacing. My local model was no better. Workplace deliverables I actually needed, like the BSBOPS501 training workbooks and appraisal reports, were out of reach.

LM-PDF Editor closed that gap: a prompts-and-utils pipeline in which a local model generated the content and the tool imposed professional structure, producing visually publication-quality PDFs and Word-compatible files a workplace could actually deliver. For its window, it was a leading-class proprietary application: nothing on the market did document authoring from a model's prose well.

Proof of concept: v14 sample (Sep–Oct 2025 build)

What the sample shows

From the three-word prompt "banana report", the v14 pipeline produced a fully formatted PDF: section headings with colored rules, a two-column table with a styled header band, aligned numeric rows and body prose, driven by a 4-billion-parameter non-reasoning model. At the time, frontier cloud models could barely style a table or a font at all.

Where the numbers in the output come from

The table values come from the model's training data. Nothing in the run validated them. The README disclaimer quoted in the section below states the operating rule: output is AI-generated and may not be accurate or verifiable.

Variation controls visible in the window

Number of outputs sets how many files one Start click produces, with no fixed cap on total runs. Enable Seed.md attaches per-output seed material, and Number of Seeds (1–99) selects how many seeded variations the user prompts through, so each output varies. Batches route round-robin across the configured backends, batch by batch.

Hardware envelope

This 2–4 page report renders in a few seconds on an RX 6800 XT. A 4B model also fits a 4 GB card, at 3–6× slower. That envelope is what makes bulk runs on ordinary hardware practical.

What it still does well

The pipeline remains an efficient generator of large volumes of test data: many document variations from short prompts, locally, with batching and seeded variation controlled from the UI.

Trade-offs it carried

Lossy by design

The formatted files looked good but were hard to edit afterwards, because the formatting lived inside the file. In 2025 that trade bought visual quality no other pipeline could produce; by 2026 it stopped being worth paying.

Ethical disclaimer published day one

In the README from the first commit: "The output is AI-generated and may not be accurate or verifiable. Users are responsible for the ethical and legal use of generated content. Do not use this tool to create fake documents, impersonate individuals, or deceive others."

Local model only

It ran entirely on a local model; workplace documents never left the machine.

Why it retired

Around four to six months after building it, the cloud model APIs gained native document authoring: proper editable formatting, tables, styles; an ordinary coding agent (no specialised tools) could now produce a better document, faster, with validation checks and live references. The capability the tool existed to compensate for stopped being special. I retired it. Maintaining a solution to a problem that no longer exists made no sense.

Durable outputs moved into the Strata agent stack.
